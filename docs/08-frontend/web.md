# Network console (web/)

The whole ChainBrain system on one screen, for the laptop demo, the judges and the presenter. The owner's own app is the phone (`mobile/`); the console shows what the phone, the agent, the pockets, the sellers and the chain are doing, together. React 19, Tailwind v4, viem (read-only), Radix dialog, lucide icons. Design: [docs/08-frontend/design-system.md](design-system.md) (v5 Neo-Kinetic Fintech after VaultBank: warm paper-grey canvas, white 20-radius cards, black pill nav, Clash Display for titles and figures (currency at 75 %) and General Sans for text, both from Fontshare's CSS API, hatch bars and verdict bands, the pocket card with the phone's VaultBank anatomy (black stripe with the agent pill, big short number, a visible edge and a sheen), the four-tile mark in the header and favicon, vermillion for the refusing gate; light only). Pockets name the agent that holds them (ChainBrain, Claude or ChatGPT, read from the pocket's immutable agent key, with the official marks in `shared/brand/`). Screenshots: `docs/08-frontend/screenshots/neo/web-*.png`.

- **No login.** Nothing to connect: the console only reads (events stream, `/api/config`, the chain).
- **Chain reads:** pockets from the factory's `PocketCreated` logs, rules and balances from the pocket contracts, history from Mock e-HKD `Transfer` and pocket `Revoked` / `RulesChanged` logs (`src/console/chain.ts`). RPC: `<api>/dev/rpc` on the dev stack, otherwise the FISCO RPC the server reports in `/api/config` (chain 20200).
- **Chip** on every page: "Test network · no real money" on the built-in network and the dev stack; "FISCO BCOS · no real money" against a real server.
- **Presenter (`#present`):** the checks path, the agent, the pocket and a docked **scorecard** (Task 40 / Security 30 / Interaction 30: pocket created, on-chain payment, co-signed, injection ignored, forced transfer reverted, data refused, rule change refused, kill switch, one clarifying question, refused then re-planned, safe stop with a fix, fix applied) ticking from what has run since presenter mode opened, each with its proof hashes. The scene stepper follows the built-in story ("Playing · scene 4") or the linked phone. Scorecard and Evidence share one set of facts (`shared/sim/proof.ts`), and the checks path reads `shared/sim/checks.ts`, so both work the same on the built-in network, a linked phone and a live server.
- **Built-in network (default).** The console opens on a network that runs in the tab (`shared/sim`, the same world the phone uses): a presenter owner whose pockets play the story on a loop (scenes 1, 4, 5 with a forced transfer that reverts, 6, 7, 8; about two minutes, 15 s rest, fresh pockets each run; scene 12, the routine pocket app, plays from the Judges tab) plus earlier history and background traffic from other owners. Live follows the presenter's active pocket unless one is picked. Judges: the red-team box, "Force the transfer", and a Play button per scene all work. The code is `shared/sim/autopilot.ts`, `src/source/localFeed.ts`, `src/console/FeedNetwork.tsx`.
- **Settings** (gear in the header): "Custom server" switch, off by default. On: a URL field, Test connection (GET /api/config, shows ms or the error) and Use this server; off returns to the built-in network. Stored in localStorage (`cb.source`, `cb.apiUrl`) and remembered. A hidden `?server=<url>` switches to a real server (used by `devstack/e2e/e2e.cjs`); `?server=builtin` switches back. Screens read one `Network` shape (`src/console/network.ts`) from either `LiveNetwork` (SSE + chain reads, today's behaviour) or `FeedNetwork`, so nothing branches on the source.
- **Transactions.** Every hash opens the in-app Explorer. No outside link is made for a hash the server's chain does not hold; on a real server the Explorer adds a link to that server's read-only `/explorer` (FISCO has no public explorer). The built-in network's hashes are virtual.
- **Linked to the phone.** `src/source/linkedFeed.ts` wraps the built-in feed (`src/source/feed.ts` is the `NetworkFeed` seam). Run `pnpm --dir devstack relay` (or the full `pnpm --dir devstack start`, which mounts the relay at `/dev/relay`) and start the phone with `EXPO_PUBLIC_API_URL=http://<laptop LAN IP>:8787` on the built-in network. The console finds the phone by itself (SSE), shows the phone's pockets first by name, follows them, and holds its own story while the phone is linked. The Judges tab's attacks (chat attacks via `say`, the fooled-agent transfer via the relay's `hijack` command), plant and force-transfer go back to the phone and run on the phone's pockets. The relay never signs or approves anything. With no phone it is the plain built-in network.

Fill a running dev stack with real purchases: `pnpm --dir devstack seed`.

The dev server may find 5173 taken by another project: `.claude/launch.json` also has `web-console-5174`. Screenshots of the pocket apps: `docs/08-frontend/screenshots/pocket-apps/c-*.png`.

Commands: `pnpm --dir web dev`, `build`, `lint`, `test`. End to end against a live stack: `node devstack/e2e/e2e.cjs`.
