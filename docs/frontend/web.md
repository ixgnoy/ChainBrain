# Network console (web/)

The whole ChainBrain system on one screen, for the laptop demo, the judges and the presenter. The owner's own app is the phone (`mobile/`); the console shows what the phone, the agent, the pockets, the sellers and the chain are doing, together. React 19, Tailwind v4, viem (read-only), Radix dialog, lucide icons. Design: [design-system/chainbrain/MASTER.md](../../design-system/chainbrain/MASTER.md) (v3: deep teal + navy, light only).

| Tab | Shows | Spec link |
| --- | --- | --- |
| **Live** (default) | Three columns. Agent trace: every tool call, its result, the rule it hit and the reason code (e.g. `SELLER_NOT_ALLOWED`), seller content quarantined as data and flagged when it looks like an instruction. The pocket: balance, status, cap, ask-me, expiry, allowed sellers, "worst case" line and its on-chain history with tx hashes. Sellers: what each shop saw from this pocket. Follows the pocket the agent touched last unless one is picked. | "Demo layout: chat with trace on the left, the active pocket on the right"; "judges watch the decision being made" |
| **Pockets** | Every pocket the factory created, read from the chain: owner, balance, rules, status | "Home: pockets as cards with balance, agent and status" |
| **Sellers** | The seller's side (finals preview): earnings, sales and refused attempts in plain language, catalogue | Finals roadmap "seller console" |
| **On-chain** | Every transaction (create, fund, payment, revoke, return, rule change) with its hash, linked to BaseScan on the real chain; forced transfers that reverted | "Every on-chain action shows its tx hash with a link to the block explorer" |
| **Judges** | Red-team box (plant text in a seller's next response), forced transfer past the agent (scene 5 backstop, dev stack), the eight demo scenes with copyable sentences and expected outcomes | "Red-team box"; "Live testing" |

- **No login.** Nothing to connect: the console only reads (events stream, `/api/config`, the chain).
- **Chain reads:** pockets from the factory's `PocketCreated` logs, rules and balances from the pocket contracts, history from USDC `Transfer` and pocket `Revoked` / `RulesChanged` logs (`src/console/chain.ts`). RPC: `<api>/dev/rpc` on the dev stack, `VITE_RPC_URL` (default `https://sepolia.base.org`) otherwise.
- **Testnet chip** on every page: "Testnet · Base Sepolia · no real money" (the dev stack says "local Base Sepolia fork").
- **Built-in network (default).** The console opens on a network that runs in the tab (`shared/sim`, the same world the phone uses): a presenter owner whose pockets play the story on a loop (scenes 1, 4, 5 with a forced transfer that reverts, 6, 7, 8; about two minutes, 15 s rest, fresh pockets each run) plus earlier history and background traffic from other owners. Live follows the presenter's active pocket unless one is picked. Judges: the red-team box, "Force the transfer", and a Play button per scene all work. The code is `shared/sim/autopilot.ts`, `src/source/localFeed.ts`, `src/console/FeedNetwork.tsx`.
- **Settings** (gear in the header): "Custom server" switch, off by default. On: a URL field, Test connection (GET /api/config, shows ms or the error) and Use this server; off returns to the built-in network. Stored in localStorage (`cb.source`, `cb.apiUrl`) and remembered. A hidden `?server=<url>` switches to a real server (used by `devstack/e2e/e2e.cjs`); `?server=builtin` switches back. Screens read one `Network` shape (`src/console/network.ts`) from either `LiveNetwork` (SSE + chain reads, today's behaviour) or `FeedNetwork`, so nothing branches on the source.
- **Transactions.** On a public chain a hash links to BaseScan. Otherwise (built-in network, local fork) it opens an in-app detail: status (Success / Reverted by the pocket), amount, from, to, block, time, full hash. No explorer links are ever made for hashes that are not on a public chain: BaseScan links appear only when connected to a real server on the public chain. The built-in network is meant for demos; its hashes are virtual.
- **Linked to the phone.** `src/source/linkedFeed.ts` wraps the built-in feed (`src/source/feed.ts` is the `NetworkFeed` seam). Run `pnpm --dir devstack relay` (or the full `pnpm --dir devstack start`, which mounts the relay at `/dev/relay`) and start the phone with `EXPO_PUBLIC_API_URL=http://<laptop LAN IP>:8787` on the built-in network. The console finds the phone by itself (SSE), shows the phone's pockets first by name, follows them, and holds its own story while the phone is linked. The Judges tab's plant and force-transfer go back to the phone and run on the phone's pockets. With no phone it is the plain built-in network.

Fill a running dev stack with real purchases: `pnpm --dir devstack seed`.

Commands: `pnpm --dir web dev`, `build`, `lint`, `test`. End to end against a live stack: `node devstack/e2e/e2e.cjs`.
