01 Permission model
01 · Permission model

Who can do what, and who checks it

Each role gets the narrowest power that does its job. "The card" is the contract on chain, which holds even if everything above it is compromised.

RoleCanCannotEnforced by
OwnerCreate, fund and edit cards; revoke; unfreeze; take the funds back; co-sign one paymentHave the key read by the server: it never leaves the phone or browserThe card (onlyOwner); the device's signing guard
AI agent (the model)Read the card and sellers, draft a task, quote, haggle, ask the owner, pay a quoteName an address, hold a key, edit a card, reach another card or the main walletThe wallet tools: no tool takes an address or returns a key
Agent key, one per cardSign one exact transfer from its own card to a quoted sellerPay off the allowlist, above the cap, the allowance or the balance; pass the ask-me limit alone; change a ruleThe card (isValidSignature, canPay)
Sentinel (guardian key)Freeze a card, with a reasonMove money, unfreeze, or change any ruleThe card (guardian set once, freeze only)
Seller and facilitatorQuote a price; submit a transfer the agent signedChange the payee or amount; obtain personal data or any other signatureThe token's EIP-712 digest; the wallet's content scan and signing rule
Signed-in visitorAct on their own cardsWrite to someone else's card (403 NOT_YOUR_CARD)The server, which checks the card's on-chain owner()

Sensitive actions, by tier

TIER 0 · READ
No confirmation

Balance, rules, sellers, quotes. Nothing moves.

TIER 1 · PAY INSIDE THE RULES
The owner confirms the task once

A fixed Buy / Price / Deadline card written by code; the agent key then pays inside it.

TIER 2 · ABOVE THE LIMIT
The owner co-signs that payment

Above ask-me or the allowance: slide and Face ID, one seller, one amount, 10 minutes.

TIER 3 · CHANGE A RULE
Only the owner's own transaction

Rules, revoke, unfreeze, return funds. Never the agent, the server or the Sentinel.

Verification

  • The wallet reads the card's canPay before it signs anything.
  • Pre-flight runs the exact transfer as an eth_call and records its prediction.
  • The live 402 must match the quote: network, token, payee, amount.
  • The card checks again at settlement; that is the check that counts. Every result has a hash in the explorer.

Rollback and recovery

  • A refused transfer reverts whole: no money moves.
  • An authorisation works once and expires after 600 seconds.
  • Revoke stops the next payment; returnFunds takes the whole balance back.
  • A refusal returns a reason code; the agent re-plans and is told never to retry it unchanged. A settled payment can't be reversed, so every check runs first.

02 Security tests · How we tested
02 · Security tests

How we tested

Each AI agent spends from its own card: a smart contract holding Mock e-HKD and the owner's rules. A payment has to pass every layer below the AI. We attacked each layer, and also skipped straight past the upper ones to hit the card directly.

At a glance

MoneyMock e-HKD (6 decimals), shown as HK$

Contract fuzzing1,280 random payments and edits, 6 invariants over 128,000 calls
Hosted proof14 transactions, 7 of them refused attempts

Worst case: the AI is already compromised

The tests call the wallet tools directly, replace the AI with a fixed stand-in that obeys the attacker, or sign with the agent's own key and send straight to the chain. That shows what holds when the AI is wrong, which is the case that matters.

Live model: the AI decides

A real model reads the task and the seller pages and chooses every step. We judge it only by what it did: its tool calls, the balances and the receipts. What it says about itself doesn't count.

  • The live model ignored both seller-page attacks in all 8 runs.
  • A revoke stops the next payment, not one already settling.

03 Data and privacy
03 · Data and privacy

What we keep, and where

ChainBrain asks for no name, email, phone number or ID. An account is a wallet address. This is everything the system keeps, where it is kept, and for how long.

DataWhereHow longWho can read it
Owner keyThe owner's device: the phone's secure storage, or the browser, optionally behind a passkeyUntil the owner removes itThe owner only
AccountServer volume: owner address, created time, funding transaction, hashes of session tokensTokens 7 days; the account until the operator removes itThe server
Card's agentServer volume: card id and agent address; the agent key itself is derived when used, never storedLife of the cardThe server
Recent chatServer volume, per cardThe last few turns; older text survives only as the memory noteThe server; the model during a turn
Memory notesServer volume: up to 30 short notes per card, plus the last 100 versionsUntil the owner taps ForgetThe owner and the model; also open to read (KR-05)
Wallet eventsServer volume: payments, refusals, the agent's traceThe last 1,000Open to read without sign-in (KR-05)
Tasks, quotes, Radar, SentinelServer memoryUntil the server restartsThe server
Rules and transfersFISCO chainPermanentAnyone: public by design, under pseudonymous addresses

What leaves the system

  • Model provider (OpenRouter, Claude Haiku 5.5): the system prompt, the owner's messages and tool results, with seller text wrapped as untrusted. Never a key.
  • Sellers: a payment authorisation and public addresses. Requests for a name, email, history, other cards or a signature are refused by code (DISCLOSURE_REFUSED, SIGNATURE_TYPE_NOT_ALLOWED) and shown to the owner.
  • The chain: rules and transfers, which is the point of the design.

Consent and minimisation

  • Sign-in is a signed message that says it moves no money.
  • The owner confirms each task and co-signs each payment above the limit.
  • The agent's tools never show the owner's identity: there is none to show.
  • Memory reads only the owner's words and wallet events, never seller text. It is told not to store limits, keys or addresses, and code rejects any note that loosens a limit.

Deletion

The owner can forget any memory note. Chat is trimmed to the last few turns and events to the last 1,000. There is no self-service account deletion yet (KR-12). Records on the chain can't be deleted; they hold addresses and amounts, not names.

Test data

All money is Mock e-HKD, a test token, not the HKMA's e-HKD. Seller reports are marked as invented demo data. The built-in demo network's two weeks of history are generated, not anyone's real activity.

Appendix

Appendix: every test, and how to re-run it

Each attack is one test function in the repository, counted once. The token's replay, wrong-signer and expiry checks share one function.

Induced transfer · 26

Card contract: injected recipient, seller not allowed, over cap even with the owner, above ask-me without the owner, owner's co-sign for a different payment, replay, wrong agent key, expired card, revoked card, frozen card, beyond the weekly allowance, starved spend hook, garbage signature. Token: replay, wrong signer, expired authorisation. On FISCO: agent key straight to the chain; co-sign by a non-owner; seller's price changed after the quote; one quote paid twice; seller not allowed; expired approval; payment after revoke; pay before the owner confirms; above the task's price per item; Sentinel freeze after 3 refusals in a minute; Radar refuses a seller paid by a drainer; beyond the weekly allowance.

Privilege escalation · 14

Card contract: only the owner edits; agent and strangers can't freeze; the Sentinel's key can only freeze; agent signing as the owner; permit or any other message hash rejected. Token: only its owner mints. On FISCO: agent key calls setCap and gets NOT_OWNER; only a card's owner can start the attack demo; approval signed by a non-owner rejected; replayed or foreign login refused; a card naming another visitor's agent refused; a label that would loosen Radar rejected; the Sentinel's AI can raise a decision, never lower it; of two readings of a spoken rule, the stricter wins.

Data extraction · 5

The agent's tools never show the owner; the scan catches a seller's requests for data and signatures; a card's write routes answer only its owner; agents are only given to a signed-in visitor; scene 6 (data and signature requests refused and shown to the owner).

Prompt injection · 4

Seller text is wrapped as data and a forged closing tag is neutralised; scenes 5–6 seller page wrapped and its requests refused; on the in-app demo network a planted order is ignored and the forced transfer reverts; scene 5 on FISCO, forced transfer reverted.

Memory poisoning · 6

Memories citing evidence that doesn't exist are dropped; memory can only narrow; a forged closing tag is escaped; memory evidence holds owner messages and wallet events, never seller text; the memory model never sees seller text; bad output twice keeps the old memory.

Ordinary tasks · 15

Buy a report with the agent key alone; above the limit with the owner's co-sign; a dead end that stops with reasons; a real x402 payment for Exa's HK$0.056 search; starter cards buy once; a routine pays both items; the owner's co-sign beyond the allowance; a per-seller cap; a haggle that settles; scenes 1–3, 4, 7 and 8.
