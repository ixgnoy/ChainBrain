01 · Evidence summary

Topic and scenario

Topic F, Agent Wallet. An owner gives an AI agent its own card: a smart contract holding Mock e-HKD and the owner's rules (which sellers, how much per payment, when to ask). The agent buys research reports from x402 sellers. Every payment is an EIP-3009 transfer from the card, which the token approves only after asking the card (ERC-1271).

What the evidence shows

  • The agent's key pays an allowed seller alone, inside the rules.
  • Above the ask-me limit, a payment settles only with the owner's co-signature.
  • A weekly allowance is counted on chain; the owner's co-signature lifts it once.
  • A compromised agent key sending straight to the chain is refused, every way we tried.

Transaction 5 in the hosted explorer: a compromised agent key sent a seller's planted transfer straight to the Mock e-HKD token, and the card refused it.

What is not in this table

The test suites and the live-model runs (in the security self-assessment) ran on a local FISCO node, so judges can't open those hashes; they are recorded in docs/evidence-fisco.json and re-checked by server/scripts/verify-evidence.ts. Only transactions on the hosted chain are listed here.

03 Reproduction guide
03 · Reproduction guide

Check it yourself

Nothing below needs a key or an account. Steps 1 to 3 only read the public chain.

1 · Open any transaction

Click a hash on page 2, or open https://fisco-api-production-85c5.up.railway.app/explorer#/tx/<hash>. The explorer shows status, block, sender, the contract called and its events.

2 · Re-fetch all 25 receipts

Python 3, standard library only. It reads the public RPC, prints block, time and status for every hash, and exits with an error if any result differs from the table.

python3 docs/submission/evidence/check_hosted.py

3 · Read a card's rules from the chain

The independent verifier rebuilds a card's rules in plain words and checks it was created by the ChainBrain factory. Add --approved approved.json to compare it with what the owner approved.

python3 verify/verify_pocket.py --rpc https://fisco-node-production.up.railway.app \
  --pocket 0x91019dDCD226aA00D3e76CD79C5bCFF9973D5374

4 · Run the proof again, with new keys

Deploys a fresh token, factory and card from keys funded by the public faucet, then sends set B's 14 transactions. New hashes, same results; it exits with an error on any mismatch.

cd server && npx tsx scripts/hosted-proof.ts

5 · Try the app

Console: fintechathon-lian-ai-nao.vercel.app (Judges tab: four one-tap attacks). Test money: fisco-api-production-85c5.up.railway.app/faucet, HK$100 per address per day.
